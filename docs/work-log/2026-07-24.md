## 1. API 키 안전 주입

- 실키는 **`ai-service/.env`만** (저장소·채팅 커밋 금지)
- [`.env.example`](../../ai-service/.env.example) — 변수명·임계값만
- [`app/main.py`](../../ai-service/app/main.py) 기동 시 `load_dotenv`

## 2. LLM 길이 라우팅 (초기 → 확정)

초기 구상: Grok / Gemini / GPT 구간 라우팅.  
**확정:** `gsk_` = **Groq**(xAI Grok 아님) · GPT/xAI 일반 챗 경로 제거.

| message 길이 | 호출 |
|--------------|------|
| ≤300 | Groq + Llama |
| 301–500 | Gemini Flash |
| >500 | Gemini Pro |
| Gemini 실패 | Groq + `[안내]` 문구 → 둘 다 실패 시 template |

관련: [`agent/llm.py`](../../ai-service/agent/llm.py), `GROQ_API_KEY` / `GOOGLE_API_KEY`

## 3. Optuna 100-trial 모델 복구

- 2-trial 스모크로 비어 있던 `models/` 보정 → **`OPTUNA_TRIALS=100`** 재학습
- 결과: `test_roc_auc` ≈ **0.9404**, threshold **0.4**

## 4. LOT → 챗봇 features · What-if · 승인 로그

- `SelectedLotContext` + `lotToChatFeatures` (mock 누락 d50/d90/operator_id 기본값)
- LangGraph: `predict → whatif → compose`, 응답 `recommendation`
- `POST /api/control/approve` → `optimization_events` (sqlite)
- API 스모크 14/14 (보안·유사3·진단·what-if·approve·Groq)

## 5. 공정 한계치 + 5초 Undo

- Setting 「공정 제어 한계치」↔ `GET|PUT /api/settings/control-bounds` ↔ `ai-service/config/control_bounds.json`
- whatif: mtime 캐시 clip + `boundary_hit` / `limit_reason`
- Approve `approved` · `POST .../approve/:id/revert` → `reverted` · 챗봇 5초 Undo 스낵바
- 배선 문서: [`docs/references/control-bounds-wiring.md`](../references/control-bounds-wiring.md)

## 6. Main LOT 행 클릭 → 자동 진단 (당일 추가)

- 「위험 LOT Top」**행 클릭** → features 주입 + 챗봇 오픈 + **O/X 자동 진단**
- 「상세」버튼으로 모달 · 모달 내 「챗봇으로 진단」
- 「챗봇 안내」칩은 API 없이 로컬 사용법 문구 (LLM이 LOT만 반복하던 UX 수정)
- prompts/template: 안내 vs 진단 요청 구분

## 7. 보안 탭 로컬 vLLM 통신망 (1-A + 2-B)

- FE: `SecurityChatbot` → `POST /api/security-chat` (세션 키 `kdt_security_chat_session_id`)
- BE: [`securityChat.ts`](../../backend/src/routes/securityChat.ts) → ai-service `/security-chat`
- AI: [`secure_llm.py`](../../ai-service/agent/secure_llm.py) — `CHAT_VLLM_BASE_URL`(:8001) + `api_key=EMPTY`만, Groq/Gemini 폴백 없음
