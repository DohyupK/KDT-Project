## 2. docs를 모노레포 루트로 이전

작업 방향·일지·계획·프롬프트·참조를 **프로젝트 전체**가 쓰도록 루트 `docs/`로 모았습니다.

| 경로 | 용도 |
|------|------|
| `docs/direction.md` | 현재 작업 방향 (항상 최신 1개) |
| `docs/work-log/` | 날짜별 상세 · 일일업무보고용 |
| `docs/plans/` | 확정 계획 요약 |
| `docs/prompts/` | 재사용 프롬프트 |
| `docs/references/` | 중요 경로·참조 |
| `docs/README.md` | docs 목차 |

- `frontend/docs/README.md`는 **안내(포인터)만** 두고, 본문 기록은 루트 `docs/`를 보도록 했습니다.
- `docs/plans/2026-07-21-nextjs-migration.md`에 마이그레이션 계획 요약을 남겼습니다.

## 3. AI 룰·스킬 구조 (전체 vs 개별)

이전 워크스페이스(`Downloads/KDT-Project`)에만 있던 룰·스킬을 현재 모노레포(`.cursor/`, `.agents/`)로 맞추고, 범위를 정리했습니다.

| 구분 | 의미 | 예 |
|------|------|-----|
| **전체 룰** | 저장소 어디를 건드려도 적용 | `main-project.mdc`, `docs-workflow.mdc` |
| **전체 스킬** | 작업을 어디에 맡길지 조율 | `project-control` |
| **개별 룰·스킬** | 특정 중요 화면·API만 | Management / Setting, `*-api` |

주요 보완:

- 문서·일지 범위가 `frontend/docs`에 묶여 있던 부분을 **루트 `docs/`** 기준으로 수정
- 페이지·API globs를 `frontend/src/...` 경로에 맞게 조정
- 중요 페이지용 개별 룰(예: management / setting) 골격 추가

## 4. README / AGENTS 역할 분리

모르는 사람이 읽어도 “어디에 무엇이 있는지” 보이도록 네 파일을 역할별로 다듬었습니다.

| 파일 | 누구용 | 담는 내용 |
|------|--------|-----------|
| 루트 `README.md` | 사람 | 저장소 지도, 실행 입구, docs·룰이 어떻게 나뉘는지 |
| 루트 `AGENTS.md` | AI | 전 패키지 공통 **짧은** 규칙 |
| `frontend/README.md` | 사람 | FE 실행·스택·구조·진행 (전체 룰 설명은 루트로) |
| `frontend/AGENTS.md` | AI | 루트 AGENTS 안내 + FE **추가** 규칙만 |

한 줄 원칙:

- **README** = 설명서 (사람)
- **AGENTS** = 수칙 규칙 (AI, 짧게)
- **docs/** = 방향·일지 (상세)

## 5. Issue / Knowledge / Inquiry 페이지 마이그레이션

원본: `Downloads/KDT-Project/src/pages/{Issue,Knowledge,Inquiry}Page.tsx`  
대상: `frontend/src/app/{issue,knowledge,inquiry}/page.tsx`

| URL | 변환 |
|-----|------|
| `/issue` | `'use client'` + `export default function IssuePage` |
| `/knowledge` | `'use client'` + `export default function KnowledgePage` |
| `/inquiry` | `'use client'` + `export default function InquiryPage` (lucide-react) |

- react-router 의존 없음 → `useRouter` 치환 불필요
- `npm run build` 성공, `/issue` · `/knowledge` · `/inquiry` 정적 생성 확인

## 6. Dashboard 마이그레이션 + 공통 AppShell

- Dashboard: Vite `DashBoardPage.tsx` → `frontend/src/app/(shell)/dashboard/page.tsx`
- Main: `/` → `/main` (`(shell)/main/page.tsx`), 루트 `page.tsx`는 `redirect('/main')`
- 공통 UI: `src/components/layout/AppShell.tsx` + `(shell)/layout.tsx`
  - 좌측 메뉴: Main / Dashboard / Issue / Knowledge / Inquiry / Management / Setting (`next/link`)
  - 상단 헤더 공유
  - Login(`/login`)만 셸 밖
- Main / Management / Setting에서 중복 사이드바·헤더 제거
- `npm run build` 성공 (`/main`, `/dashboard` 포함)

## 7. 페이지 연동 · Login 진입점

셸 적용 페이지끼리 좌측 메뉴로 이동 가능하도록 정리했고, Login은 셸 밖이지만 **어디서든 들어갈 수 있게** 헤더에 연결했습니다.

| 구분 | 연동 |
|------|------|
| `/` | `/main`으로 리다이렉트 |
| 좌측 메뉴 | Main · Dashboard · Issue · Knowledge · Inquiry · Management · Setting (`next/link`) |
| 헤더 유저 아이콘 | `/login`으로 이동 (UI는 placeholder, 라우트·진입만 준비) |
| `/login` | AppShell 없음 (독립 페이지) |
