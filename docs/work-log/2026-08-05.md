## 현재 사항 · 계획 (스냅샷)

### 현재 사항 (완료·반영)

| 영역 | 상태 |
|------|------|
| `lots` | 공정만 (`id`, `timestamp`, 공정9, `operator_id`). `residual_li` **DROP**. QC CSV 재적재 완료. |
| `judgment_lots` | `lot_id` / `quality_defect` / `capacity` / `residual_li`. FK→`lots.id`. 시드·score NULL-fill. |
| `analysis_lots` | AI·SPC 채점 저장. score/폴러가 UPSERT. |
| SPC→앱 | `SPC_LOT` → `lots` 미러 + score. backend **60초 폴링** (`SPC_SYNC_*`). 수동 `npm run sync:spc-lots`. |
| API residual | `residualLithium` ← `judgment_lots.residual_li` (BE JOIN). |
| 대시보드 LOT 위험등급 | LOT ID · **불량확률(`probability`)** · 잔류 · 규격대비. SPC/위험/상세차트 빈칸. |
| 네모칸(불량확률·SPC·위험등급·상세) | **빈칸** (의도적 후속). |
| orphan SPC | `spc_limits` TABLE 등 DROP 완료. 앱 SPC는 JSON/`analysis_lots` 쪽. |
| Public 문서 | [`Documents/Public/db-table-*-2026-08-05.md`](../../Documents/Public/) 동기. |

데이터 흐름(운영):

```text
plant_feeder → SPC_LOT
       ↓ (backend 60s poll / npm run sync:spc-lots)
     lots (공정)
       ↓ score AI
  analysis_lots + judgment_lots(NULL만 채움)
       ↓
  dashboard LOT 위험등급 (jl residual 3컬럼)
```

참고: score/폴러는 기존 `ensureIssuesForRiskLots`도 호출함 (심각·주의 → `issues`). 사용자가 새로 요청한 기능명은 아님.

2. **judgment `quality_defect` / `capacity` FE** — 화면 노출.

## SPC_LOT → lots → AI judgment (NULL만)

**상태:** 싱크 스크립트 + score가 judgment 3컬럼 NULL-fill.

| 단계 | 동작 |
|------|------|
| 미러 | `SPC_LOT`에만 있는 `lot_id` → `lots` INSERT (공정·timestamp) |
| 채점 | 신규 id만 `scoreAllLots({ lotIds })` → `analysis_lots` |
| 판정 | `judgment_lots` UPSERT: `quality_defect`/`capacity`/`residual_li`는 **NULL일 때만** AI |
| AI | `/predict` · `/predict-capacity` · `/predict-residual` |

- 스크립트: `cd backend && npm run sync:spc-lots` (`--skip-score` 가능)
- `SPC_LOT_results` 실측은 judgment에 복사하지 않음
- `issues`: 위험 LOT만 `ensureIssuesForRiskLots` (전원 stub 없음)
