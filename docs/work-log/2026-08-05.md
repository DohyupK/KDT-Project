## SPC_LOT → lots → AI judgment (NULL만)

**상태:** 싱크 스크립트 + score가 judgment 3컬럼 NULL-fill.

| 단계 | 동작 |
|------|------|
| 미러 | `SPC_LOT`에만 있는 `lot_id` → `lots` INSERT (공정·timestamp) |
| 채점 | 신규 id만 `scoreAllLots({ lotIds })` → `analysis_lots` |
| 판정 | `judgment_lots` UPSERT: `quality_defect`/`capacity`/`residual_li`는 **NULL일 때만** AI |
| AI | `/predict` · `/predict-capacity` · `/predict-residual` |

- 스크립트: `cd backend && npm run sync:spc-lots` (`--skip-score` 가능)
- `SPC_LOT_results` 실측은 judgment에 복사하지 않음
- `issues`: 위험 LOT만 `ensureIssuesForRiskLots` (전원 stub 없음)

## `lots` / `analysis_lots` 분리 (BE JOIN)

**상태:** DDL·BE 조회/채점/rollback 반영. 원격 마이그레이션·데이터 TRUNCATE/재적재는 **사용자**. FE Issue/Main 목업 교체 **범위 밖**.

### 스키마

| 테이블 | 컬럼 요지 |
|--------|-----------|
| `lots` | 공정 SSOT + `residual_lithium` (점수/위험/버전/`scored_at` 제거) |
| `analysis_lots` | `defect_prob`, `spc_status`, `risk_level`, `risk_reason`, model versions, `scored_at` |

- CREATE/시드: [`DB/schema.sql`](../../DB/schema.sql) · [`DB/issue_lot_tables.sql`](../../DB/issue_lot_tables.sql) · [`DB/issues_seed.sql`](../../DB/issues_seed.sql)
- 구조만 마이그레이션(행 복사 없음): [`DB/migrate_lots_to_analysis_lots.sql`](../../DB/migrate_lots_to_analysis_lots.sql)

### 백엔드

| 영역 | 변경 |
|------|------|
| `lot.service` | `LOT_SELECT` = `lots` LEFT JOIN `analysis_lots` · 채점→`lots.residual_lithium` + `analysis_lots` UPSERT |
| `dashboard.service` | 위험 목록/상세/생산추이/CSV JOIN |
| `issue.service` | 과거 자료 LOT JOIN · 시스템 인수인계 LOT는 공정 컬럼만 INSERT |
| `rollback-score-lots` | `analysis_lots` 점수 NULL + `lots.residual_lithium` NULL |

API camelCase 필드명은 유지. `residual_margin`은 계속 API 계산.

문서: [`backend/README.md`](../../backend/README.md) · [`docs/references/issue-lot-api.md`](../references/issue-lot-api.md)

### 운영자 체크리스트
