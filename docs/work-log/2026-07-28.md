# 2026-07-28 업무일지

## 요약

오늘 핵심은 **레지스트리 다중 헤드(clf → capacity → residual)** 를 챗·What-if·Approve까지 한 줄로 잇고, **잔여 리튬(residual_li) 본학습**까지 끝낸 것.

- clf / reg / residual은 **별도 모델** — 숫자는 서로 대체하지 않음. 실측 상관(저용량↑불량, 고잔여↑불량, residual↔capacity 음의 상관)은 compose `data_note`로만 설명.
- features 채팅: `registry.json`에서 `ready: true`인 헤드 **전부 자동 호출** (피커 없음).
- What-if 선정: **불량 확률↓ → residual↓ → capacity↑**.
- Approve 후 **실측 outcome**만 저장 (가짜 CSV·합성 데이터 금지).
- 보안 탭 API 금고 UI 복구 · LLM 키는 DB만 (`.env` API 폴백 없음).
- Login / MariaDB · TS 불량률(기상) · RAG/vLLM: **보류/다음**.

## 1. 모델·데이터 역할

| 헤드 | 데이터 | 타깃 | API | 산출 |
|------|--------|------|-----|------|
| clf | `cathode_clf_data.csv` | `quality_defect` O/X | `POST /predict` | `models/` |
| reg | `cathode_reg_data.csv` | `capacity` mAh/g | `POST /predict-capacity` | `models/reg/` |
| residual | `cathode_qc_reg_data.csv` | `residual_li` ppm(예시) | `POST /predict-residual` | `models/residual/` |

- Feature: 공정 수치 9개 + `operator_id` + 동일 `add_domain_features`.
- clf는 capacity/residual을 **입력으로 쓰지 않음**.
- `id`는 clf↔reg↔qc 전량 조인 가능(실측).
- TS (`cathode_ts_data.csv`): 파일만 존재, **기상 CSV 확보 전 학습 안 함**.

스키마 문서:

- [`docs/references/cathode-clf-schema.md`](../references/cathode-clf-schema.md)
- [`docs/references/cathode-reg-schema.md`](../references/cathode-reg-schema.md)
- [`docs/references/cathode-residual-schema.md`](../references/cathode-residual-schema.md)

### residual EDA (실측, 학습 전 정리)

- 2500–3500: 정상 다수(양산 중심)
- 3500–4500: 불량 폭증
- ≥5000: 불량 > 정상; ≥6500: 정상 0
- residual ↔ capacity: r ≈ −0.66 (잔여↑ → 용량↓)

## 3. What-if · Approve · 실측 outcome

### What-if (초기: clf+capacity → 후반 residual 포함)

| 시점 | 선정 규칙 |
|------|-----------|
| 오전~중반 | 불량 확률 최소 → 동률 시 capacity 최대 |
| 후반(현재) | 불량↓ → **residual↓** → capacity↑ |

- suggestion: `capacity_before` / `capacity_after` / `unit`
- 후반 추가: `residual_before` / `residual_after` / `residual_unit`
- 한계치 타협: `boundary_hit` · `limit_reason` (Setting bounds)

### control / UI

- Approve: `optimization_events`에 capacity(·residual) before/after 저장
- `POST /api/control/approve/:id/outcome` — 실측 `outcome_quality_defect`(0|1), 선택 `outcome_capacity`
- GlobalChatbot: 승인 → 5초 Undo → 실측 입력 UI (**가짜 데이터 없음**)
- 관련: `optimization-event-schema.md` 등 control 문서

## 5. residual_li 헤드 (후반 · 완료)

### 결정

- 데이터: 기존 `ai-service/data/cathode_qc_reg_data.csv` (10k, 실측)
- 학습 뼈대: capacity와 동일 (Optuna 100, XGB+Cat 0.5/0.5, RMSE, seed 42, TimeSeriesSplit)
- 단위: **ppm (placeholder)**
- 챗: ready 헤드 전부(clf+capacity+residual)
- What-if: 3단 선정 + residual before/after 인용
- TS 학습: **이번 스프린트 제외**
