## 요약

- Capacity×불량률 차트는 **실측 분포** 상관이며, clf/reg는 **별도 모델**.
- 챗봇 features 경로에서 **registry ready 헤드 전부 자동 호출**(현재 clf+reg).
- `/predict-capacity` API · ChatResponse `capacity`/`heads` · backend·frontend 타입 포워드.
- What-if가 **clf+capacity**를 같이 보고, Approve 후 **실측 outcome**만 기록.

## 모델 역할 정리

| 모델 | 입력 | 출력 | capacity↔불량 |
|------|------|------|----------------|
| clf | 공정 피처 (capacity 없음) | defect_status / probability | 학습 타깃이 불량 라벨; capacity를 직접 학습하지 않음 |
| reg | 동일 공정 피처 | capacity mAh/g | 용량만 예측 |
| compose | predict + capacity JSON + data_note | 사용자 답변 | 저용량↑불량 비율 경향을 **설명용**으로만 언급 |

## What-if capacity · 실측 outcome

- 선정: 불량 확률 최소 → 동률이면 capacity 큰 쪽
- `suggestion.capacity_before` / `capacity_after` / `unit`
- Approve: `capacity_before`/`capacity_after` 컬럼 저장
- `POST /api/control/approve/:id/outcome` — 실측 `outcome_quality_defect`(0|1), 선택 `outcome_capacity`
- GlobalChatbot: 승인 후 실측 입력 UI (가짜 데이터 생성 없음)
- 문서: `optimization-event-schema.md`
