# 챗봇 메뉴별 답변 개선 보고서

작성일: 2026-08-20  
대상: 일반 챗봇의 메뉴 컨텍스트 답변, 선택 항목 답변, DB/Qdrant 장애 폴백

관련 문서: [`chatbot-review.md`](./chatbot-review.md), [`chatbot-code-before-after.md`](./chatbot-code-before-after.md)

## 작업 결과

일반 챗봇이 페이지 데이터를 JSON 형태로 나열하던 방식을 메뉴별 업무 요약으로 변경했다. 메인, 대시보드, 이슈, 지식, 문의, SPC, 설정 화면에서 각각 다른 항목과 우선순위를 사용해 답변한다.

답변에 노출되던 내부 경로, 구현 용어, 코드값도 사용자용 문구로 바꿨다.

- 제거한 표현 예: `현재 화면 (/dashboard)`, `포커스 데이터`, `page_payload`, `primary_table`
- 변환한 표현 예: `HIGH` → `높음`, `pending` → `대기`, `warning` → `경고`
- 선택 항목은 `선택한 이슈`, `선택한 LOT`, `선택한 문의`처럼 현재 메뉴에 맞춰 표시한다.

## 수정한 문제

### 1. 메뉴와 관계없이 화면 데이터만 나열하던 문제

수정 전에는 화면 컨텍스트가 있어도 경로와 JSON 데이터를 그대로 붙이는 템플릿이 사용됐다.

수정 후에는 다음 메뉴별 답변 계약을 적용한다.

| 메뉴 | 주요 답변 항목 |
| --- | --- |
| 메인 | 주요 KPI, 위험 LOT, Q-COST, 우선 확인 사항 |
| 대시보드 | 위험 LOT 건수, 우선 확인 LOT, 불량 가능성, SPC 상태, 다음 확인 |
| 이슈 | 열린 이슈, 고위험, 담당자 미지정, 조치 대기, 처리 순서 |
| 지식 | 과거 이슈, 인수인계, 선택 문서, 참고 자료, 후속 확인 |
| 문의 | 전체·필터 문의 수, 답변 대기, 우선 처리 문의 |
| SPC | 표시 패널, 조회 기간, 선택 패널, 차트 확인 안내 |
| 설정 | 글자 크기, 테마, 자동 새로고침, 알림 상태, API 키 보호 안내 |

외부 LLM을 사용하는 경로에도 같은 답변 계약을 전달한다. 외부 LLM이 비활성인 경우에는 로컬 템플릿이 같은 구조로 답한다.

### 2. 선택 항목이 원시 JSON으로 표시될 수 있던 문제

선택 LOT뿐 아니라 이슈, 지식 자료, 문의, SPC 항목을 사용자 문구로 요약하는 선택 항목 전용 응답을 추가했다.

예를 들어 이슈 선택 시 다음 순서로 답한다.

1. 선택한 이슈 ID
2. 관련 LOT
3. 위험도
4. 담당자
5. 처리 상태
6. 이슈 내용

알려진 필드가 없는 항목도 JSON을 출력하지 않고 현재 화면에서 상세 정보를 확인하도록 안내한다.

### 3. 화면 요약 문장을 일부 인식하지 못하던 문제

`현재 화면을 요약해 주세요.`의 목적격 조사 `을`이 기존 정규식에 포함되지 않아 일반 대화 경로로 빠지던 문제를 수정했다.

다음과 같은 표현을 화면 요약 의도로 처리한다.

- 이 화면 요약
- 이 페이지를 정리해 줘
- 지금 보고 있는 화면
- 현재 화면을 요약해 주세요

### 4. DB 장애가 화면 질문 전체를 지연시키던 문제

백엔드가 대시보드·이슈 데이터를 보강하기 위해 MariaDB를 동기적으로 기다리면서 10~20초 이상 지연되던 문제를 수정했다.

- 페이지 데이터와 선택 항목 보강을 병렬 실행한다.
- 기본 제한 시간은 1,200ms다.
- 제한 시간을 넘기거나 조회가 실패하면 프런트가 이미 전달한 현재 화면 데이터를 사용한다.
- `PAGE_CHAT_HYDRATE_TIMEOUT_MS` 환경 변수로 제한 시간을 조정할 수 있다.

### 5. Qdrant 장애 시 BGE 모델을 불필요하게 로드하던 문제

단기 대화 이력이 없는데도 장기 벡터 이력 검색을 실행해 BGE-M3 모델을 로드하고 Qdrant 연결을 반복하던 경로를 수정했다.

- 단기 이력이 없으면 벡터 이력 검색을 생략한다.
- Qdrant TCP 연결을 먼저 확인한다.
- Qdrant 연결이 확인된 이후에만 BGE 임베딩 모델을 로드한다.
- 동시 초기화 방지 잠금을 적용한다.
- 초기화 실패 후 기본 30초 동안 재시도를 유예한다.
- Qdrant 클라이언트 호환성 확인을 비활성화해 불필요한 추가 연결을 막는다.

## 검증 결과

검증 환경에서는 MariaDB와 Qdrant가 실행되지 않아 백엔드 레거시 세션 저장소를 `memory`로 사용했다.

| 테스트 | 결과 |
| --- | --- |
| 대시보드 메뉴 일반 응답 | 1,446ms, 메뉴별 위험 요약 정상 |
| 이슈 메뉴 일반 응답 | 28ms, 우선순위와 다음 처리 순서 정상 |
| 지식 메뉴 일반 응답 | 27ms, 과거 이슈·인수인계·선택 문서 요약 정상 |
| 문의 메뉴 최종 스모크 테스트 | 117ms, 답변 대기 현황과 다음 처리 정상 |
| 선택 이슈 최종 스모크 테스트 | 1,237ms, 관련 LOT·위험도·담당자·상태·내용 정상 |
| 대시보드 SSE 스트리밍 | 1,340ms, `meta`·`delta`·`done` 이벤트 정상 |
| 7개 메뉴 단위 검사 | 메인·대시보드·이슈·지식·문의·SPC·설정 모두 통과 |
| 내부값·원시 JSON 검사 | 내부 경로, `HIGH`/`pending`, JSON 키 및 객체 나열 없음 |
| Qdrant 장애 동시 초기화 | 동시 3회 요청을 약 508ms 내 처리, BGE 모델 미로드 |
| Python 구문 검사 | 변경한 AI 서비스 파일 모두 통과 |

테스트를 위해 실행한 백엔드와 AI 서비스 프로세스는 검증 후 종료했다.

## 남은 범위

이번 작업에는 다음 항목을 포함하지 않았다.

- 실제 운영 MariaDB가 연결된 상태의 장기 대화 저장 검증
- 실제 Qdrant가 연결된 상태의 의미 기반 장기 대화 검색 검증
- 활성 외부 생성형 LLM별 메뉴 출력 계약 준수 평가
- 보안 챗봇의 MariaDB 큐·Qdrant 문서·로컬 vLLM 통합 답변 검증
- 채팅 API 인증, 스레드 소유권, LLM 키 API 보호 문제
- 보안 대화의 브라우저 `localStorage` 저장 문제

백엔드 전체 production build는 이번 변경과 무관한 `backend/src/services/analysisLotSyncPoller.ts`의 `fillRecommendedActionsForLots` 미정의 오류가 남아 있어 통과하지 않는다.
